My top design decision is to roll out every edge release as a ring-based canary (1 → 5 → 20 → 50 sites) using layered IoT Hub deployments on Azure IoT Edge 1.6 LTS, with a metric gate and automatic fallback to the last known-good release, instead of a blue-green swap. A bad model or image can then leave damage undetected at one pilot site for at most one soak period instead of at all 50 sites, and operators can roll it back with a PR revert rather than kubectl, which directly limits the financial loss from missed damage. The effort is modest — about three days per fleet rollout, gated on health metrics the system already collects — and unlike blue-green it needs no second inference stack on the 2 GB edge PCs, so all 50 sites can be on the release by week 5, before the week-6 freeze.
