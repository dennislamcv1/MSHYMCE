1. MODEL SPECIFICATIONS
--------------------------------------------------------------------------------
Model Name:          FraudShield-v3 (Gradient Boosting Classifier)
Framework:           XGBoost 2.1.0 + Scikit-learn 1.5.0
Model Type:          Binary classification (fraud / not-fraud)
Input Features:      47 engineered features (see Feature Catalog below)
Output:              Probability score [0.0 – 1.0] + binary decision

Performance Baseline (Holdout Test Set, 30 days):
  • AUC-ROC:         ≥ 0.94
  • Precision@0.5:   ≥ 0.82
  • Recall@0.5:      ≥ 0.91
  • F1-Score:        ≥ 0.86
  • Inference Latency (p99): ≤ 120 ms per transaction
  • Throughput:      ≥ 28 transactions/second per endpoint instance

Model Size:          ~18 MB (pickled XGBoost model + preprocessing pipeline)
Artifact Size:       ~45 MB (model + conda env + scoring script)

Feature Catalog (Top 15 by importance):
  1. amount_log                     (numeric)
  2. hour_of_day                    (categorical encoded)
  3. day_of_week                    (categorical encoded)
  4. is_weekend                     (boolean)
  5. merchantCategory_encoded        (categorical encoded)
  6. isOnline                        (boolean)
  7. distance_flag                   (categorical: 0=local, 1=regional, 2=international)
  8. avg_txn_amount_30d             (numeric, rolling window)
  9. txn_count_24h                  (numeric, rolling window)
 10. unique_merchants_7d            (numeric, rolling window)
 11. time_since_last_txn_minutes    (numeric)
 12. amount_vs_avg_ratio            (numeric)
 13. velocity_score_1h              (numeric, engineered)
 14. device_risk_score              (numeric, external API derived)
 15. geo_anomaly_flag               (boolean, rule-based)

  • Model rollback decisions must have approval traceability

6. INCIDENT HISTORY
--------------------------------------------------------------------------------
Incident #1 — "Silent Drift" (2025-11-14)
  • Symptom: Fraud detection rate dropped from 2.3% to 0.8% over 6 days unnoticed
  • Root Cause: Merchant category distribution shifted due to new partner onboarding;
                model was not retrained on new category encodings
  • Impact: $340K in undetected fraudulent transactions
  • Lesson: Need automated drift detection with alerting within 4 hours

Incident #2 — "Deployment Rollback Failure" (2026-01-08)
  • Symptom: v2.4 deployment caused latency spike to 890 ms (p99)
  • Root Cause: Scoring script bug in feature preprocessing; rollback to v2.3 took
                23 minutes due to manual steps and missing rollback automation
  • Impact: 12-minute service degradation, 4,200 transactions delayed
  • Lesson: CI/CD must include automated rollback with < 5 min recovery time

Incident #3 — "Storage Cost Spike" (2026-03-22)
  • Symptom: Blob Storage bill increased 340% month-over-month
  • Root Cause: Experiment artifacts accumulated unchecked; no lifecycle policy
  • Impact: $18K unbudgeted spend; 4.2 TB of redundant data
  • Lesson: Automated lifecycle policies with retention rules are mandatory

Incident #4 — "Feature Store Latency" (2026-05-03)
  • Symptom: Feature retrieval latency spiked to 450 ms during peak hours
  • Root Cause: Feature store (custom Redis) was single-node, no auto-scaling
  • Impact: 8% of transactions exceeded 200 ms SLA
  • Lesson: Feature store must be scalable and decoupled from scoring latency

8. BUSINESS COST MODEL (for Threshold Justification)
--------------------------------------------------------------------------------
Cost per False Negative (missed fraud):    $127  (average fraud transaction value)
Cost per False Positive (blocked legit):   $8    (customer service + friction cost)
Cost per hour of service downtime:         $45,000 (revenue loss + SLA penalties)
Cost per hour of delayed scoring (>200ms): $3,200 (queue buildup + manual review)

Break-even analysis for drift:
  • If drift causes 1% drop in recall: expected loss = $1,270/hour
  • Therefore, drift detection + retraining cost must be < $1,270/hour to be ROI-positive
